# 论文知识库插件设计说明

## 知识库文本选择

插件不把阅读页当前选中的文本版本当作知识库来源，而是调用朗读器的专用接口 `GET /api/papers/{paper_id}/knowledge`。接口按以下顺序选择：

1. 明确标记为知识库文本的手动导入版本；
2. DeepSeek 读图识别版本；

如果两者都不存在，插件跳过该论文，不会索引自动识别文本或朗读优化文本。

返回结果包含正文分段和隐藏元信息（论文标题、作者、摘要）。插件上传时把元信息作为一个独立前置文本块，正文仍保持原来的分段；元信息不会进入 PDF 阅读正文、朗读优化或 TTS 任务。

## 数据边界

| 数据 | 权威来源 | 插件行为 |
| --- | --- | --- |
| 原 PDF、文件夹、正文、语音包 | PDF-Listen-Read | 只读获取 |
| 论文标题、作者、摘要 | PDF-Listen-Read 隐藏知识库元信息 | 只读获取 |
| 向量、倒排索引、重排序与检索结果 | AstrBot 原生知识库 | 创建、更新、删除 |
| `paper_id -> AstrBot doc_id` 映射 | 插件数据目录 | 用于安全删除与增量同步 |

## 同步规则

1. 定时读取朗读器的 `GET /api/papers`。
2. 新论文或 `updated_at` 变化的论文，读取 `GET /api/papers/{id}/knowledge` 的知识库文本和隐藏元信息。手动导入且明确设为知识库文本的版本优先于读图识别版本；上传时先放入标题、作者、摘要，再放入正文分段。单篇论文超过 96 个文本块时拆成多个较小索引文档，降低 NAS 上单次 SQLite/FAISS 写入压力。
3. 同一论文内容或标题变化时，先删除旧 `doc_id`，再写入新文档，避免旧向量残留。
4. 上游列表中已不存在的 `paper_id`，删除其对应的 AstrBot 文档。
5. 如果 AstrBot 目标知识库被手动删除，丢弃旧 `doc_id` 映射，下一轮同步完整重建。

## 为什么预览不提供编辑

论文文本可在 PDF-Listen-Read 中经过人工编辑或大模型整理；若插件页面也能修改片段，会出现两个文本来源和不可预测的覆盖顺序。因此页面只用于查看同步状态、Provider ID 和索引片段，编辑统一回到朗读器后再同步。

## 模型使用

插件使用 `context.kb_manager`，即 AstrBot 4.27 自带的知识库能力；Embedding Provider 是必需项，Rerank Provider 是可选项。插件页面会列出已加载模型的 ID，复制到插件设置后即可使用，不保存任何模型 API Key。
